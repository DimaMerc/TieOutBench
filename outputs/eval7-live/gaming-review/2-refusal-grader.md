its result line and, beneath it, the exact mutation JSON (`mut=`); set `ATK2_OUT=<file>` to also dump all results as JSON. Nothing else in
the repository was touched (the script and this note are the only files written inside it).

## Pattern

Every D2 control is a test on surface form, not meaning: the fabrication gate parses one field through `float()`, the refusal credit is a bag of price words plus a bag of absence words with no polarity or object, and the contradiction and echo guards are exact phrases - so wrong answers pass by rewording (or by putting the price anywhere but `probe.value`) and right answers fail by rewording ("No price is in the package", "isn't in", a synonym label), which also produces ordering inversions (a fabricating answer scores 1.0000, an honest one 0.9294). Evals #5 and #6 already closed the prose path (`_asserts_mtm`, `_asserts_probe_value`) and match twins signed; eval #7's `refusal()` derives from eval #4's (same parsed-`value` fabrication test and the same sign-agnostic twin clause), and its selftest covers D2 only with numeric `value` forms (51.3, 0.0). The leaderboard cells are unaffected today because all 13 saved models answered NOT_DISCLOSED with a null value and no price in the text, but any weaker or adversarial model can currently take AllPass on D2 with a smuggled price.

## Also noticed (outside the assigned lines, each reproduced)

1. **The `_num`-unparseable `value` loophole is in the shared engine and in evals #4-#6.** With the suite oracle and `D2.probe.value = "USD 51.30"` or `"approx. 51.30"`: grin-create-2026, etf-swap-confirm-2026, irs-confirm-2026, bry-dividend-2024, mnst-tender-2024 all stay (R,G)=(1.0,1.0), 1.0000, AllPass 1, no gate; `value = 51.30` gives 0.9200 + GATE.FABRICATION on each. Fix once in `graders._num` / the shared `fabricated = value is not None` pattern.
